# BIOTORF Business OS · Vue-версия

Прототип на Vue 3 + Pinia (данные в localStorage). Разделы CRM, карточка клиента и новая лента «Коммуникации» уже работают; остальные вьюхи — заглушки до переноса из демо v0.9.

## Запуск

```bash
npm install
npm run dev     # http://localhost:5173
npm run build   # production-сборка в dist/
```

## Раздел «Коммуникации» (входящие/исходящие звонки и сообщения)

Задача клиента: **не искать человека в телефонной книжке или Telegram, а вести всё общение внутри сервиса.**

Что реализовано (демо-уровень):

- **Единая лента** (`src/views/CommsView.vue`, пункт меню «☎ Коммуникации», виден всем ролям):
  - каналы: звонок (телефония), Telegram, WhatsApp; направление входящее/исходящее;
  - автопривязка записи к клиенту по `farmId`; непривязанные («неизвестный номер/ник») можно привязать кнопкой «Привязать»;
  - фильтры: Все / Звонки / Telegram / WhatsApp / Непрочитанные + сквозной поиск;
  - клик по строке открывает карточку клиента; кнопка «Ответить» пишет исходящее сообщение прямо в ленту;
  - «＋ Зафиксировать» — ручная запись звонка (итог, длительность, резюме) или сообщения.
- **Карточка клиента**: новая вкладка «Связь» — вся история звонков и переписки по этому хозяйству + быстрый ответ клиенту, не выходя из карточки.
- **Реестр клиентов**: колонка «Связь» со счётчиком записей и бейджем непрочитанных.
- **Топбар**: иконка ☎ с количеством непрочитанных сообщений.
- **Хранилище**: коллекция `comms` в `stores/db.js` (actions: `addComm`, `markCommRead`, `markAllCommsRead`, `linkCommToFarm`), примеры данных — в `data/sample.js`.

Формат записи:

```js
{ id, kind: 'call'|'telegram'|'whatsapp', dir: 'in'|'out',
  farmId | null, contact, phone, handle, text | note,
  status, duration, ts, read }
```

## Как это будет работать по-настоящему (роадмап интеграций)

Демо-лента имитирует поток, который в промышленной версии наполняется автоматически:

1. **IP-телефония** (Asterisk / UIS / Манго Офис / Zadarma): webhook CDR на каждый звонок → сервер создаёт запись `comms`, сверяя номер с базой контактов; missed call автоматически ставит задачу «перезвонить».
2. **Telegram Bot API**: бот в чатах с клиентами (или пользовательский MTProto-клиент/интегратор типа Wazzup, Retell) → входящие сообщения пушатся в ту же ленту; ответ из сервиса уходит через `sendMessage`.
3. **WhatsApp Business Cloud API**: двусторонний обмен, шаблоны, статусы доставки.
4. **Серверная часть** (`backend/main.py`, FastAPI): эндпоинты `POST /comms/webhook/{telephony|telegram|whatsapp}`, `GET/POST /comms`, таблица `communications` в PostgreSQL, нормализация телефонов (`E.164`) для матчинга с контактами.
5. **Матчинг неизвестных контактов**: совпадение по номеру/@nick → предлагается привязка к существующему хозяйству или создание лида из сообщения в один клик.

> В demo-режиме реальные персональные данные клиентов в ленту не вносить (см. главное README репозитория).
