# Подключение Telegram к BIOTORF Business OS

Сообщения клиентов из Telegram автоматически попадают в раздел **«Коммуникации»**
и привязываются к клиенту по номеру телефона. Воркер работает через **long-poll**
(getUpdates) — публичный HTTPS-сервер **не нужен**, всё запускается локально в Docker Desktop.

```
Клиент → @ваш_бот → api.telegram.org ← telegram-worker (Docker) → POST /webhooks/telegram → SQLite → лента «Коммуникации»
```

## Шаг 1. Создать бота

1. В Telegram откройте **@BotFather**.
2. Команда `/newbot` → имя (например, `BIOTORF Агро`) и username (например, `biotorf_agro_bot`).
3. Скопируйте выданный **токен** вида `123456789:AAH...`.
4. Команда `/setprivacy` → выберите бота → **Disable** — иначе бот не будет видеть сообщения в группах.

## Шаг 2. Прописать токен в .env

Откройте файл `.env` в корне проекта (создан из `.env.example`) и заполните:

```env
TELEGRAM_BOT_TOKEN=123456789:AAH_ваш_токен
TELEGRAM_WEBHOOK_SECRET=придумайте-длинную-случайную-строку
```

> Воркер и бэкенд используют один и тот же секрет — при его смене перезапустите оба контейнера.

## Шаг 3. Запустить стек с профилем `tg`

```bash
docker compose --profile tg up -d --build
```

Появится третий контейнер `biotorf-tg-worker`. Проверка:

```bash
docker logs biotorf-tg-worker --tail 20
# должно быть: [tg-worker] polling -> http://backend:8787/webhooks/telegram
```

## Шаг 4. Написать боту

Напишите боту сообщение **с другого аккаунта/телефона** (имитация клиента):

```
Здравствуйте! Нужна консультация по обработке полей пшеницы.
```

Через несколько секунд запись появится в ленте **http://localhost:8080 → Коммуникации**:
- тип: Telegram, направление: входящее;
- автор: имя + @username из Telegram;
- если у клиента в реестре (`farms.json`) есть номер телефона, совпадающий с тем, что он передал контактом — запись привяжется к хозяйству автоматически.

Проверить можно и через API:

```bash
curl -s "http://localhost:8787/api/comms?channel=telegram" | python -m json.tool
```

## Как это работает внутри

| Компонент | Роль |
|---|---|
| `backend/telegram_worker.py` | Долгий опрос Bot API (getUpdates), пересылка апдейтов на вебхук с заголовком `X-Bot-Secret`. При старте сам сбрасывает назначенный webhook (защита от ошибки 409). |
| `POST /webhooks/telegram` (backend/main.py) | Валидирует секрет, извлекает текст/автора/время, идемпотентно сохраняет запись (по `update_id`), автопривязка к клиенту. |
| Фронтенд «Коммуникации» | Отображает ленту, фильтры по каналу, отметку прочтения. |

## Частые проблемы

- **Записей нет** → `docker logs biotorf-tg-worker`: проверьте, что токен верный и воркер не падает с `401 Unauthorized`.
- **409 Conflict** → с этим токеном уже где-то крутится другой поллер/вебхук. Новый воркер вызывает `deleteWebhook` при старте; если проблема осталась — остановите дублирующий процесс.
- **Бот молчит в группе** → включён privacy-режим: `/setprivacy` → Disable, затем передобавьте бота в группу.
- **Секрет не совпадает** → `TELEGRAM_WEBHOOK_SECRET` в `.env` должен быть одинаковым для backend и worker (compose подставляет одну переменную обоим).
- **Перезапуск без потери истории**: данные в volume `dbdata`; полная очистка ленты — `docker compose down -v`.

## Дальше (боевой режим)

- Исходящие ответы прямо из ленты: добавить вызов `sendMessage` Bot API из backend (заготовка — тот же токен).
- Перенос на webhook-режим возможен при наличии публичного HTTPS: `setWebhook https://ваш-домен/webhooks/telegram?secret=...` — тогда воркер не нужен.
